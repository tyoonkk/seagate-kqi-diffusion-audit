# 재생성 실험 사전 등록 문서 v1 — 계열 A (제출한 Seagate 논문, MDPI Electronics electronics-4573451)

상태: **동결본** (결과를 보기 전에 작성. 동결 기록은 `REGEN_FREEZE_V1.json` 이며 이 문서와 실행·분석 코드의 SHA-256 을 담는다.)
작성: 2026-10-07. 계열 B(DR-HERC)·C(fab_lot_audit)와 무관하다.

## 1. 왜 다시 만드는가

- 심사위원 2 는 과거 확산 실험이 완전히 재현되지 않고(합성 행렬 미보존) 축소 설정으로 돌았다는 점(의견 6), 분류기가 LightGBM 하나뿐이라는 점(의견 4),
  9개 과제와 독립이 아닌 seed 로 안정성을 따져야 한다는 점(의견 3)을 지적했다.
- 원고 전체 팩트체크에서 보관 생성기가 사실상 학습되지 않았음이 확인됐다(`handoff/SEAGATE_MDPI_FACTCHECK_2026-10-07_KO.md` 1절).
  주 감사 후보는 10 epoch, 동일예산 아카이브는 200 epoch 이었지만 손실이 0-예측 수준(약 1.0)에 머물렀다. 생성 뒤 1–99% 자르기도 특징 26–81% 를 상수로 만들었다.
- 따라서 "검증 기반 선택 정책이 일반화되는가"라는 논문의 질문을, **실제로 학습된 생성기**로 만든 후보에 대해 같은 감사 절차로 다시 묻는다.
  공저자 동의 아래 사용자가 이 재실험을 지시했다(2026-10-07).

## 4. 생성기가 학습됐는지 확인하는 기준 (결과를 보기 전에 정한다)

생성기마다(과제 × seed × 모드) 다음을 기록한다. 모두 학습 자료 안에서만 잰다.
1. 학습 확인(필요조건): 떼어 둔 불량에서 연속 부분 잡음 예측 손실 < 특징 독립 가우시안 기준, 그리고 이진 부분 KL 손실 < min(학습 비율 기준, 복사 기준).
   0-예측 손실도 함께 적는다.
2. 품질 서술: 떼어 둔 불량 대 합성 불량 C2ST AUC (LightGBM 5겹 교차검증, 부분표본 5번 평균), DCR 비, 기억 지표(mem_p05), KS, 상관 오차,
   이진 1 비율 오차, 실제 불량에서는 변하는데 합성에서 상수인 특징 수, 내부 TSTR(학습 음성 80% + 합성 불량 → 나머지 음성 20% + 떼어 둔 불량)과 실제 불량으로 한 같은 값.
- 1 을 만족하지 못한 생성기가 있으면 그 사례를 빼지 않고 그대로 보고하며, 해당 과제의 결과 해석에 표시한다.
- 2 는 품질 서술용이다. 결과를 보고 사례를 빼거나 다시 돌리는 데 쓰지 않는다.
- 알려진 한계(결과 전 기록): 범주 변수가 많은 과제(예: 과제 10)는 고친 생성기의 합성 불량도 떼어 둔 실제 불량과 쉽게 구별된다(진단 4차 C2ST 1.000).
  같은 자료의 고전 기준(가우시안 코풀라, 독립 주변분포)도 같았고 SMOTE 만 0.80 이었다. 논문에는 이 점을 생성기 진단과 함께 그대로 쓴다.

## 5. 분석 (분류기마다, 과제 묶음마다)

과제 묶음: **보관 9개(주)**와 **전체 11개(부)**. 분류기: **LightGBM(주, 원고와 같은 분류기)**과 XGBoost(부).
감사 계산은 원래 스크립트의 함수를 그대로 쓴다(`build_regen_audits_v1.py`). 이 래퍼에 보관 입력을 넣으면 논문 수치가 그대로 나오고,
후보·reference 선택 규칙이 보관 선택과 135/135, 45/45, 45/45, 45/45 일치함을 확인했다(`validate_regen_audits_v1.py`).

1. **주 감사 (원고 표 4·5)**: 격자 A family winner 에 7개 과제 ID 없는 게이트, 바깥 과제 하나 빼기, conservative 와 mean_only 목표.
   보고: 선택 수, 음수 행 수, 과제 거시 평균 Δ PR-AUC, 과제 재표집 구간(default_rng(20260714), 10,000번).
2. **동일예산 LOTO (원고 표 3·알고리즘 1)**: 격자 B 고정 후보에 과거 5개 게이트, 같은 바깥 선택 규칙.
3. **맞춘 비교 (원고 5.3절)**: {과거 5, 단순 7 거부형, 단순 7 후보 수준} × {conservative, mean_only, harm_first}.
4. **안정성 (심사위원 2 의견 3)**: 과제별 평균, 과제 하나를 뺀 과제 거시 평균(잭나이프), seed 별 분포.
5. **분류기 의존성 (의견 4)**: 같은 사례에서 두 분류기가 고른 행동이 같은 비율, 둘 다 하이브리드를 고른 사례의 Δ 부호 일치.
6. **생성기 진단 요약**: 4절의 지표를 과제·모드별로 표로 (`build_regen_generator_table_v1.py`).
7. **후보 자체의 test 차이 (서술)**: 선택 없이 격자 A family winner 와 격자 B 24개 후보가 reference 보다 test 에서 나은 비율과 평균 차이를 과제별로 센다.

## 6. 해석 규칙 (결과를 보기 전에 정한다)

- 주 결론은 1 번(LightGBM, 보관 9개)의 두 목표로 판단한다.
  - conservative 가 다시 모두 기권하고 mean_only 의 과제 거시 Δ 가 0 이하이거나 구간이 0 을 포함하면:
    "생성기를 고쳐도 검증 기반 선택 정책은 일반화되지 않았다"로 원고의 주 결론을 유지한다.
  - mean_only 또는 conservative 가 하이브리드를 고르고 과제 거시 Δ 구간이 0 보다 위에 있으면:
    이를 새 결과로 보고하고 제목·초록·결론을 그에 맞게 고친다. 과거 결과와 새 결과를 나란히 보고한다.
- 2·3 번은 원고와 같이 과거 시험 노출이 있는 게이트 묶음이므로 민감도 분석으로만 해석한다.
- XGBoost 와 11개 과제 결과는 일반화 범위를 보여 주는 부 분석이다. 주 결론과 방향이 다르면 그대로 적는다.
- 어떤 결과도 "효과가 없다"의 증명으로 쓰지 않는다. 9(또는 11)개 과제와 독립이 아닌 seed 라는 한계를 함께 적는다.

## 7. 실행 규칙

- 출력 폴더는 한 번만 쓴다. 같은 판(version)을 다시 돌리지 않는다. 중단되면 같은 코드·설정 해시일 때만 끝난 사례를 건너뛰며 이어 간다(manifest 대조).
- 시험 운전: 짧은 생성기 설정(500 단계)으로 과제 0 seed 42 를 `--no-test` 로 돌려 실행기 전 경로를 확인했다
  (가우시안판 `smoke_regen_v1_task0_notest` 15분, 혼합형판 `smoke_regen_v1mixed_task0_notest` 6.5분). test 평가 경로는 S0 하나로 따로 확인했다. 이 결과는 쓰지 않는다.
- 본 실행: `run_regen_archive_v1.py --run-name regen_archive_v1_run1 --generator-config generator_config_v3_final.json`.
  프로세스 두 개로 나눠 돌린다(과제 묶음 {10, 9, 4, 0, 3} 과 {7, 2, 6, 1, 5, 8}). 같은 출력 폴더·같은 manifest 를 쓰며, 실행기는 코드·설정 해시가 같을 때만 이어서 쓴다.
- 감사 래퍼는 test 값을 보기 전에 동결하고 해시를 동결 기록에 남긴다. 코드 경로 시험은 `--fake-test`(무작위 test 값)로만 했다.
- 동결 기록에는 이 문서, 실행기, 생성기 코드(v2·v3), 생성기 설정 JSON, run_pipeline.py, 중요도 표, 감사 래퍼·검증기·생성기 표 도구, 원래 감사 스크립트의 SHA-256 을 남긴다.
